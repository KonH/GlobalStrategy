# Spec: Damage and Durability at War

## Feature Intent

As a game designer, I want every country that is currently a war participant (per the war-mechanics-core model from GitHub issue #69 / `Docs/Specs/26_07_25_06_war-mechanics-core`) to expose two derived country-scoped war resources — **damage** and **durability** — computed from a per-country config baseline (1–100, reflecting 1880-era war technology) plus the relevant ruler and advisor character skills, and recalculated whenever those characters or skills change, so that a later battle/combat slice can consume stable, queryable offensive and defensive war strength without re-deriving skill math itself.

## Acceptance Criteria

- **Given** war mechanics core is available (`Wars.IsInWar` / `WarParticipant`, per issue #69) and a country is not currently a participant in any war **When** that country's war resources are queried **Then** it does not expose live `damage` / `durability` war resources for combat use — those resources exist only for countries that are currently at war.
- **Given** two countries enter a war (e.g. via `DebugDeclareWarCommand` or any future natural declaration path that creates `WarParticipant` rows) **When** the war is created **Then** each participant country immediately gets country-scoped `damage` and `durability` resource values computed from that country's configured base plus its current ruler and relevant advisor skills.
- **Given** a country is at war **When** its `damage` is computed **Then** the value is derived from that country's configured base damage (integer range 1–100, authored to reflect common understanding of that country's war technology circa 1880) combined with the ruler's military skill and the military advisor's military skill (in this codebase: the character `power` skill resource on roles `ruler` and `military_advisor`).
- **Given** a country is at war **When** its `durability` is computed **Then** the value is derived from that country's configured base durability (integer range 1–100, same 1880 war-tech baseline idea) combined with the ruler's stinginess skill and the economic advisor's stinginess skill (character `stinginess` skill resource on roles `ruler` and `economic_advisor`).
- **Given** a country's base damage and base durability are defined in config **When** those values are authored **Then** each is an integer in `[1, 100]`, stored per country (not a single global tunable), and is the static baseline before skill contributions are applied.
- **Given** a country is at war and its ruler, military advisor, and/or economic advisor is replaced (e.g. via the existing `DebugCycleCharacterCommand` country-character cycle, which swaps the character entity and re-rolls that character's skill resources) **When** the character change is applied **Then** that country's `damage` and/or `durability` are recalculated immediately from the new characters' current skills — not deferred to a month boundary.
- **Given** a country is at war and a skill value that feeds damage or durability changes on the currently assigned ruler or relevant advisor **When** that skill change is applied **Then** the affected war resource(s) are recalculated immediately to reflect the new skill value(s).
- **Given** only one of damage's or durability's contributing roles/skills changed **When** recalculation runs **Then** only the resource(s) that depend on the changed inputs are required to update; the other resource may be left unchanged if its inputs were untouched, as long as both remain correct relative to current config + skills.
- **Given** a country stops being at war (e.g. via `DebugStopWarCommand` / `Wars.StopWar`) **When** the war ends **Then** that country's live `damage` and `durability` war resources are removed (or otherwise cease to be exposed as active war resources) for both former participants, matching the "resources while at war" framing.
- **Given** attacker country A and defender country B are both in the same war **When** each side's damage/durability are read **Then** each country has its own independently computed pair based on *that* country's config bases and *that* country's characters — one side's skills do not affect the other side's values.
- **Given** damage and durability have been computed for a country at war **When** any other system or a future battle slice needs to read them **Then** they are queryable as country-scoped values (same general resource-query style other country resources use) without the consumer re-deriving skill math. No battle consumer is implemented in this feature.
- **Given** a save is loaded while a war is active **When** init/load completes **Then** each war participant's `damage` and `durability` match a fresh computation from current config bases + current character skills (correct immediately after load, not stale until the next character change or month tick).

## Out of Scope

- Any usage, consumption, spending, or modification of `damage` / `durability` by battles, combat resolution, war progress, or any other gameplay consumer — that is a separate future spec (issue framing: "usage of those resources related to battles").
- Any change to war declaration, war ending, war progress, or the `War` / `WarParticipant` / `WarProgress` model from issue #69 / `Docs/Specs/26_07_25_06_war-mechanics-core` beyond reading participation to know who is at war.
- Any consumption or interaction with the existing `recruits` resource (despite the parent issue title "Recruits usage"); this slice only introduces damage/durability derivation.
- Any player-facing UI/HUD/tooltip dedicated to damage or durability. Surfacing through existing generic resource display paths is allowed only if it falls out of the chosen storage shape with no new UI work; otherwise UI remains deferred.
- Natural war declaration, peace resolution, allies / multi-country wars, or any battle simulation.
- New character roles, new skill ids, or changes to how character skills are seeded/cycled — this feature only reads existing `power` / `stinginess` on existing `ruler` / `military_advisor` / `economic_advisor` roles.
- Bot/AI strategy that chooses wars or battles based on damage/durability.

## Ambiguities

- [NEEDS CLARIFICATION: Exact combination formula for final damage/durability — e.g. `base + rulerSkill + advisorSkill`, weighted sum, average, multiply, or another rule — and whether the result is clamped to `[1, 100]`, allowed to exceed 100, or floored/ceiled to integers.]
- [NEEDS CLARIFICATION: Confirm that "military skill" in the issue maps to the existing character skill resource id `power` (there is no skill id literally named `military`), and that "stinginess" maps to the existing `stinginess` skill id (issue text sometimes shortens it to "stingness").]
- [NEEDS CLARIFICATION: Where per-country base damage/durability live in config — new fields on `CountryEntry` in `country_config.json` (preserved across GeoJSON regen like `historicalFriends`), a separate war/military config file, or another home — and who authors the concrete 1–100 values for the ~20 `isAvailable: true` countries (and whether unavailable countries need bases too).]
- [NEEDS CLARIFICATION: Lifecycle storage shape — create/destroy ordinary country `Resource{ResourceId="damage"|"durability"}` entities on war start/end; keep them always seeded but only "active"/meaningful while at war; or a non-`Resource` derived component recomputed on demand. The acceptance criteria require at-war-only exposure but do not prescribe the ECS shape.]
- [NEEDS CLARIFICATION: Persistence — treat damage/durability as fully derived (omit `[Savable]`, recompute on load) vs persist as normal `[Savable]` resources that must still be force-recomputed on load to avoid skill drift. Country-scoring precedent prefers derived/non-savable for recomputable values.]
- [NEEDS CLARIFICATION: Missing-character edge case — if a war participant somehow has no ruler, no military advisor, and/or no economic advisor (or the skill resource is missing), should the missing skill contribution be treated as `0`, block resource creation, or is this impossible by init invariants and therefore undefined?]
- [NEEDS CLARIFICATION: Aside from `DebugCycleCharacterCommand` (character swap + skill re-roll), is there any in-scope mechanism that mutates an existing character's skill `Resource.Value` in place? If not, "skill changes" in acceptance criteria may only be reachable via character replacement today, with in-place skill mutation reserved for a future cheat/mechanic.]
- [NEEDS CLARIFICATION: Should `damage` / `durability` appear in `VisualState.SelectedCountry.Resources` / `resource_config.json` display whitelist for debug inspection, or remain backend-only until a battle UI exists?]
