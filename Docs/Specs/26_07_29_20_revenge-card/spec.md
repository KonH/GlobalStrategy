# Spec: Revenge Card

## Feature Intent

As a player, I want to play a "Revenge" action card against a country whose military establishment I've built real influence with, so that I can drag my organization's home country into a war against that country as a direct, player-facing declaration of war, instead of war only ever being started through debug tooling.

## Acceptance Criteria

Legend: `Precondition => Action => Outcome`, grouped under a shared precondition where one applies to several rows.

- The playing org's Control in the selected country is below 20, or its Opinion with the selected country's military advisor is below 25, or either the selected country or the org's home country is currently in a war with anyone.
  - The deck/draw system evaluates a free hand slot for this country => "Revenge" is not eligible to be drawn into the org's hand.
- The playing org's Control in the selected country is 20 or higher, its Opinion with the selected country's military advisor is 25 or higher, and neither the selected country nor the org's home country is currently in a war.
  - The deck/draw system evaluates a free hand slot => "Revenge" is eligible to be drawn like any other country card, subject to the normal per-slot draw fill — there is no "push into hand the instant the condition becomes true" mechanic; eligibility is only re-checked the next time a slot is actually being filled.
  - A copy is in hand and its 50-gold cost is affordable => the card is shown as playable.
  - A copy is in hand but its 50-gold cost is not affordable => the card is shown as unplayable for the ordinary insufficient-funds reason, same as every other card.
- A copy of "Revenge" is already sitting in hand and any of the three conditions above later becomes false (Control drops below 20, Opinion drops below 25, or either country enters a war through any means) before that copy is played.
  - The player opens the country's Actions panel => the card is shown unplayable via the same conditions-gated check every other card already goes through; it stays in hand, it is not discarded for this reason. This is the same "not available while war is ongoing" behavior referenced below — a live re-evaluation of the standard gate, not a one-time or permanent lockout. If the war later ends by any means and Control/Opinion still hold, the copy becomes playable again the next time the panel re-evaluates it.
- The player plays "Revenge" while all three conditions hold, and its 50-gold cost is paid.
  - The play always succeeds — there is no roll of any kind. A new war is declared between the org's home country (attacker) and the selected country (defender); the card leaves the hand and a replacement is drawn into the vacated slot as usual.
  - The newly declared war starts with a temporary bonus for the attacker only (the org's home country; the defender is unaffected): the attacker's `damage` and `durability` country resources — each already continuously computed as `base + skillA + skillB` by the always-present `damage`/`durability` resource collectors from issue #71 — are increased by +10% and +5% respectively on top of whatever that live collector-computed value would otherwise be. The bonus is a percentage of the live formula output (base plus current ruler/advisor skills), not of the config base alone, so it tracks any later skill or character changes automatically.
  - Each month, the bonus decays: the damage bonus percentage drops by 1 percentage point and the durability bonus percentage drops by 0.5 percentage points, both configurable, until each reaches 0 and stops contributing to the collector-computed value. The decay does not remove or end the war itself — only the bonus fades.
- Another copy of "Revenge" is sitting in the same country's hand while the war this card started (or any war) between the org's home country and that country is still ongoing.
  - The player opens the Actions panel => the copy is shown unplayable, per the standard "no war" draw/play condition re-evaluating false — same mechanism as the first bullet group above, not a new discard behavior.
- The war between the org's home country and the selected country, started by this card, ends because the org's home country wins it.
  - Intent (not implemented by this iteration): any remaining copy of "Revenge" sitting in that country's hand should eventually be discarded outright (removed from hand entirely, not merely shown unplayable) once a war can be won means something to the codebase. No war-outcome/victory-determination mechanic exists yet anywhere in the codebase (issues #74 "Peace resolution", #80 "War progress logic", and #82 "War result window" are all open/unimplemented), so this iteration does not invent a win signal or implement the discard. See Out of Scope.
  - The war ends for any other reason (e.g. a debug stop-war, or a future non-victory resolution) => no discard of any kind happens for this reason, in this or any future iteration — the card simply falls back to "unplayable, stays in hand" via the standard no-war-gate re-evaluating, exactly like the general case above. Only a win (once definable) is in scope for a future discard.

## Tech Notes

- **New action definition** in `Assets/Configs/action_config.json`: `revenge`, `ownerType: "country"`, `targetRole: "military_advisor"`, `cost: [{ "resourceId": "gold", "amount": 50.0 }]`, `deckCopies: 3` (same as `sphere_of_pressure` / `decrease_enemy_control`), following the shape of `sphere_of_pressure`/`decrease_enemy_control`/`make_friend`.
- **Role-parameterized Opinion gate — generalizes existing hardcoded logic, does not touch other cards' behavior:** `ActionPlayability.Evaluate` (`src/Game.Systems/ActionPlayability.cs:20`) and `DrawCardSystem.DrawCountryCards` (`src/Game.Systems/DrawCardSystem.cs:94`) both currently hardcode `CharacterQuery.GetTargetCharacterByCountryAndRole(world, countryId, "diplomacy_advisor")` to populate `ExpressionContext.Opinion`. `CharacterQuery.GetTargetCharacterByCountryAndRole` (`src/Game.Systems/CharacterQuery.cs:6`) is already role-agnostic. Both call sites should read the role from `ActionDefinition.TargetRole` (`src/Game.Configs/ActionConfig.cs:15`, already exists but currently unused for this purpose) instead of the literal `"diplomacy_advisor"` string, so `Opinion` resolves against whichever role a given card names — `military_advisor` for Revenge, `diplomacy_advisor` unchanged for Make Friend/Make Rival. `Control` stays org+country-only (`ControlQuery.GetOrgControlInCountry`, no role param) — unaffected.
- **New "war-free" DSL gate** — new `WarFree` double field (1.0/0.0) on `ExpressionContext` (`src/Game.Configs/ExpressionNode.cs`) plus a `case "warFree": return ctx.WarFree;` branch, following the same precomputed-scalar pattern as `Control`/`Opinion`/`HasSuitableRelationTarget`. Both `ActionPlayability.Evaluate` and `DrawCardSystem.DrawCountryCards` compute it as `!Wars.IsInWar(world, countryId) && !Wars.IsInWar(world, hqCountryId)`, where `hqCountryId` is resolved via `OrganizationConfig.FindById(orgId).HqCountryId` (`src/Game.Configs/OrganizationConfig.cs`). The `revenge` action's `conditions` array combines `gte(control, 20)`, `gte(opinion, 25)`, and `gte(warFree, 1)`. Because this gate is re-evaluated live every time playability/draw is checked (not cached at draw time), it already produces the "not available while war is ongoing, playable again once war-free" behavior described in the Acceptance Criteria without any extra state.
- **Declare-war effect** — new `DeclareRevengeWarEffectParams : ActionEffectDefinition` in `src/Game.Configs/EffectConfig.cs`, registered in `ActionEffectDefinitionListConverter`'s switch, carrying the configurable bonus amounts (see below). Resolved inline in `CreateActionEffectSystem.Update`'s effect dispatch (no marker component/new system needed for the declare call itself, mirroring `decrease_enemy_control`'s inline `ControlQuery` calls rather than `Make Friend`'s deferred-marker pattern, since no `Random`/proximity data is needed): resolve `hqCountryId` via `OrganizationConfig.FindById(orgId).HqCountryId`, then call `Wars.DeclareWar(world, hqCountryId, countryId, currentTime)` directly, and on success attach the new `RevengeWarBonus` component described below to the attacker.
- **Damage/durability bonus — layered on the landed always-present collector design (issue #71 / PR #93, merged):** `damage`/`durability` are ordinary, always-present country `Resource` entities (`src/Game.Systems/DamageCollector.cs`, `DurabilityCollector.cs`), each recomputed by an Instant+Daily absolute collector as `target = base + skillA + skillB` via `WartimeSkillQuery.GetSkill` (`src/Game.Systems/WartimeSkillQuery.cs`) and config bases from `CountryCombatBases` (`src/Game.Configs/CountryCombatBases.cs`), registered under `DamageCollector.Id`/`DurabilityCollector.Id` in `ResourceCollectorRegistry.CreateDefault` (`src/Game.Systems/ResourceCollectorRegistry.cs`). They are computed for *every* country, at war or not — there is no wartime-only lifecycle to hook into.
  - New `RevengeWarBonus` component (e.g. `{ WarId, CountryId, DamageBonusPercent, DurabilityBonusPercent }`) attached to the attacker country when `Wars.DeclareWar` succeeds from the `revenge` effect, seeded at `10.0`/`5.0`. A new `RevengeWarBonusQuery` (mirroring `Wars.IsInWar`'s archetype-scan shape) exposes `GetBonusPercent(world, countryId, "damage"|"durability")`, returning `0` when no component exists for that country — so every country with no active bonus behaves exactly as the landed #71 design already does.
  - `DamageCollector`/`DurabilityCollector` gain a bonus lookup (constructor-injected the same way `combatBasesByCountryId` already is, or read live via `RevengeWarBonusQuery` since they already receive `world`) and change their `target` computation from `base + skillA + skillB` to `(base + skillA + skillB) * (1 + bonusPercent / 100)`, so the bonus rides on top of the live, always-current formula output (including any later skill/character changes) rather than being applied once at declaration time. This is additive to the existing collectors, not a fork — non-attacker and peacetime countries keep the exact `base + skillA + skillB` behavior from the #71 spec since their bonus percent is always `0`.
  - A new monthly decay step, analogous to `WarSystem.Update`'s `WarProgress` decay (`src/Game.Systems/WarSystem.cs`), reduces `RevengeWarBonus.DamageBonusPercent` by a new configurable `RevengeDamageBonusDecayPerMonth` (default `1.0`) and `DurabilityBonusPercent` by `RevengeDurabilityBonusDecayPerMonth` (default `0.5`) on `GameSettings` (`src/Game.Configs/GameSettings.cs`, sibling to `AttackerWarProgressDecayPerMonth`), each clamped at a floor of `0`. Because the collectors re-derive from the component every collection pass, decaying the component is sufficient — no separate write-back to the `damage`/`durability` resources is needed.
- **Discard-on-win — deferred, no new machinery in this iteration:** every existing conditions-gated card (`decrease_enemy_control`, `stop_friendship`/`stop_rivalry`, `make_friend`/`make_rival`) leaves an in-hand copy that fails its condition sitting unplayable forever — none of them discard it. The closest existing shape for a future discard is `RemoveCardFromHandSystem`'s two-line pattern (`world.Remove<CardInHand>(e); world.Add(e, new CardDiscard())`, `src/Game.Systems/RemoveCardFromHandSystem.cs`), currently only triggered by a played card's own success/failure outcome (`CardUse` + `ActionSucceeded`/`ActionFailed`), never by an unrelated background condition. Building this requires a war-outcome/victory-determination signal that does not exist yet (issues #74, #80, #82 are all open); no such signal is invented here. When one of those issues lands, this spec's discard-on-win intent (Acceptance Criteria above) should be revisited as a follow-up feature rather than folded silently into whichever of #74/#80/#82 lands first.

## Out of Scope

- Any UI for the player to manually choose the target country — like every other country card, the target is always the currently-selected country whose Actions panel the card is drawn into.
- Any success/failure roll for this card — it always succeeds once played, per the issue's explicit "always succeeded".
- Full implementation of the discard-on-win behavior — blocked on a war-outcome/victory-determination mechanic that does not exist yet anywhere in the codebase (issues #74, #80, #82 are all open). This includes deciding exactly which in-hand copies would be discarded (only the copy tied to the war-triggering play, or every "Revenge" copy in that country's hand) — deferred along with the rest of the behavior, not resolved here.
- Any change to how wars are declared, stopped, or decayed for any purpose other than this card's attacker-only bonus (`Wars.cs`/`WarSystem.cs` core behavior from issue #69 is unchanged; the `damage`/`durability` collector formulas from issue #71 are extended, not replaced).
- Any bot/AI strategy for playing this card.
- Card artwork generation — placeholder art is acceptable, consistent with every prior country-card spec.
- Re-balancing the cost, conditions, or mechanics of any other existing country card as a side effect of generalizing the Opinion-role resolution.
