# Spec: Revenge Card

## Feature Intent

As a player, I want to play a "Revenge" action card against a country whose military establishment I've built real influence with, so that I can drag my organization's home country into a war against that country as a direct, player-facing declaration of war, instead of war only ever being started through debug tooling.

## Acceptance Criteria

Legend: `Precondition => Action => Outcome`, grouped under a shared precondition where one applies to several rows.

- The playing org's Control in the selected country is below 20, or its Opinion with the selected country's military advisor is below 25, or either the selected country or the org's home country is currently in a war with anyone.
  - The deck/draw system evaluates a free hand slot for this country => "Revenge" is not eligible to be drawn into the org's hand.
- The playing org's Control in the selected country is 20 or higher, its Opinion with the selected country's military advisor is 25 or higher, and neither the selected country nor the org's home country is currently in a war.
  - The deck/draw system evaluates a free hand slot => "Revenge" is eligible to be drawn like any other country card, subject to the normal per-slot draw fill — there is no "push into hand the instant the condition becomes true" mechanic; eligibility is only re-checked the next time a slot is actually being filled.
  - A copy is in hand and its 50-gold cost is affordable => the card is shown as playable.
  - A copy is in hand but its 50-gold cost is not affordable => the card is shown as unplayable for the ordinary insufficient-funds reason, same as every other card.
- A copy of "Revenge" is already sitting in hand and any of the three conditions above later becomes false (Control drops below 20, Opinion drops below 25, or either country enters a war through any means) before that copy is played.
  - The player opens the country's Actions panel => the card is shown unplayable via the same conditions-gated check every other card already goes through; it stays in hand, it is not discarded for this reason.
- The player plays "Revenge" while all three conditions hold, and its 50-gold cost is paid.
  - The play always succeeds — there is no roll of any kind. A new war is declared between the org's home country (attacker) and the selected country (defender); the card leaves the hand and a replacement is drawn into the vacated slot as usual.
  - The newly declared war starts with a temporary bonus in the attacker's favor: +10% to the attacker's war damage and +5% to the attacker's war durability, on top of whatever those values would otherwise be. [NEEDS CLARIFICATION: the `damage`/`durability` country-at-war resources this bonus modifies come from issue #71 / PR #93 (`feature/damage-durability-at-war`), which is not yet merged to `main`. This card's implementation is blocked on that merge; see Tech Notes and Out of Scope.]
  - Each month, the bonus decays: the damage bonus drops by 1 percentage point and the durability bonus drops by 0.5 percentage points, both configurable, until each reaches 0 and stops mattering. The decay does not remove or end the war itself — only the bonus fades.
- Another copy of "Revenge" is sitting in the same country's hand while the war this card started (or any war) between the org's home country and that country is still ongoing.
  - The player opens the Actions panel => the copy is shown unplayable, per the standard "no war" draw/play condition re-evaluating false — same mechanism as the first bullet group above, not a new discard behavior.
- The war between the org's home country and the selected country, started by this card, ends because the org's home country wins it.
  - Any remaining copy of "Revenge" sitting in that country's hand is discarded outright (removed from hand entirely, not merely shown unplayable) and no replacement is drawn for military-advisor-Revenge reasons — this is a new behavior; no existing card discards an in-hand copy purely because a background condition became true. [NEEDS CLARIFICATION: no war-outcome/victory-determination mechanic exists anywhere in the codebase yet (issues #74 "Peace resolution", #80 "War progress logic", and #82 "War result window" are all open/unimplemented) — there is currently no way to know a war was "won" as opposed to ended by any other means (debug stop, future peace resolution, mutual exhaustion). This bullet cannot be implemented until one of those issues lands and defines what "won" means and how it's surfaced. See Out of Scope.]
  - The war ends for any other reason (e.g. a debug stop-war, or a future non-victory resolution) => [NEEDS CLARIFICATION: does the card get discarded too, or does it simply fall back to "unplayable, stays in hand" like the general no-war-gate case above? The issue text only calls out the won-a-war case explicitly.]

## Tech Notes

- **New action definition** in `Assets/Configs/action_config.json`: `revenge`, `ownerType: "country"`, `targetRole: "military_advisor"`, `cost: [{ "resourceId": "gold", "amount": 50.0 }]`, following the shape of `sphere_of_pressure`/`decrease_enemy_control`/`make_friend`. [NEEDS CLARIFICATION: `deckCopies` was not specified in the issue; existing similar cards default to 3 — assume 3 unless told otherwise.]
- **Role-parameterized Opinion gate — generalizes existing hardcoded logic, does not touch other cards' behavior:** `ActionPlayability.Evaluate` (`src/Game.Systems/ActionPlayability.cs:20`) and `DrawCardSystem.DrawCountryCards` (`src/Game.Systems/DrawCardSystem.cs:94`) both currently hardcode `CharacterQuery.GetTargetCharacterByCountryAndRole(world, countryId, "diplomacy_advisor")` to populate `ExpressionContext.Opinion`. `CharacterQuery.GetTargetCharacterByCountryAndRole` (`src/Game.Systems/CharacterQuery.cs:6`) is already role-agnostic. Both call sites should read the role from `ActionDefinition.TargetRole` (`src/Game.Configs/ActionConfig.cs:15`, already exists but currently unused for this purpose) instead of the literal `"diplomacy_advisor"` string, so `Opinion` resolves against whichever role a given card names — `military_advisor` for Revenge, `diplomacy_advisor` unchanged for Make Friend/Make Rival. `Control` stays org+country-only (`ControlQuery.GetOrgControlInCountry`, no role param) — unaffected.
- **New "war-free" DSL gate** — new `WarFree` double field (1.0/0.0) on `ExpressionContext` (`src/Game.Configs/ExpressionNode.cs`) plus a `case "warFree": return ctx.WarFree;` branch, following the same precomputed-scalar pattern as `Control`/`Opinion`/`HasSuitableRelationTarget`. Both `ActionPlayability.Evaluate` and `DrawCardSystem.DrawCountryCards` compute it as `!Wars.IsInWar(world, countryId) && !Wars.IsInWar(world, hqCountryId)`, where `hqCountryId` is resolved via `OrganizationConfig.FindById(orgId).HqCountryId` (`src/Game.Configs/OrganizationConfig.cs`). The `revenge` action's `conditions` array combines `gte(control, 20)`, `gte(opinion, 25)`, and `gte(warFree, 1)`.
- **Declare-war effect** — new `DeclareRevengeWarEffectParams : ActionEffectDefinition` in `src/Game.Configs/EffectConfig.cs`, registered in `ActionEffectDefinitionListConverter`'s switch, carrying the configurable bonus amounts (see below). Resolved inline in `CreateActionEffectSystem.Update`'s effect dispatch (no marker component/new system needed for the declare call itself, mirroring `decrease_enemy_control`'s inline `ControlQuery` calls rather than `Make Friend`'s deferred-marker pattern, since no `Random`/proximity data is needed): resolve `hqCountryId` via `OrganizationConfig.FindById(orgId).HqCountryId`, then call `Wars.DeclareWar(world, hqCountryId, countryId, currentTime)` directly.
- **Damage/durability bonus — blocked on unmerged dependency:** issue #71 / PR #93 (`feature/damage-durability-at-war`, not yet in `main`) introduces wartime-only country `Resource` entities `damage`/`durability`, created in `Wars.DeclareWar` and destroyed in `Wars.StopWar`, computed via Instant+Daily absolute resource collectors from config bases + character skills. This card's "+10%/+5% attacker bonus, decaying 1/0.5 points per month" must be layered on top of that system once it exists — most likely as a new per-war bonus-percent component (e.g. `RevengeWarBonus { WarId, DamageBonusPercent, DurabilityBonusPercent }`) feeding an additional resource collector, decayed monthly by a new system analogous to `WarSystem.Update`, with the two decay rates added to `GameSettings`/`game_settings.json` (sibling to `AttackerWarProgressDecayPerMonth`) so they're configurable per the issue's explicit ask. The exact component/system shape is deferred until #93 merges and its actual `Resource`/collector wiring can be read directly rather than guessed. [NEEDS CLARIFICATION: is the +10%/+5% bonus a percentage of the attacker's *base* damage/durability, or of the live (skill-adjusted) value at declaration time? Does it apply only to the attacker (org's home country) or could a symmetric "revenge" narrative imply anything for the defender? The issue text ("declare new war with damage 10% bonus...") reads as attacker-only but this is not explicit.]
- **Discard-on-win mechanic — new machinery, no existing precedent:** every existing conditions-gated card (`decrease_enemy_control`, `stop_friendship`/`stop_rivalry`, `make_friend`/`make_rival`) leaves an in-hand copy that fails its condition sitting unplayable forever — none of them discard it. The closest existing shape is `RemoveCardFromHandSystem`'s two-line pattern (`world.Remove<CardInHand>(e); world.Add(e, new CardDiscard())`, `src/Game.Systems/RemoveCardFromHandSystem.cs`), currently only triggered by a played card's own success/failure outcome (`CardUse` + `ActionSucceeded`/`ActionFailed`), never by an unrelated background condition. A "discard this specific in-hand card because a war it's tracking was won" system would need to: (a) know which war/country pairing a given in-hand `Revenge` copy is "about" (every copy in a given country's hand is about that same country, so no new per-instance target component should be needed, unlike `RelationCardTarget`); (b) know the war concluded via a win specifically, not any other end state — which is the part with no data source yet (see the Ambiguity above). No implementation is proposed here beyond the pattern pointer, pending #74/#80/#82.

## Out of Scope

- Any UI for the player to manually choose the target country — like every other country card, the target is always the currently-selected country whose Actions panel the card is drawn into.
- Any success/failure roll for this card — it always succeeds once played, per the issue's explicit "always succeeded".
- Full implementation of the damage/durability bonus mechanic — genuinely blocked on issue #71 / PR #93 merging to `main` first; this spec documents intent and the likely shape, not a buildable design, until that dependency lands.
- Full implementation of the discard-on-win behavior — genuinely blocked on a war-outcome/victory-determination mechanic that does not exist yet anywhere in the codebase (issues #74, #80, #82 are all open).
- Any change to how wars are declared, stopped, or decayed for any purpose other than this card (`Wars.cs`/`WarSystem.cs` core behavior from issue #69 is unchanged).
- Any bot/AI strategy for playing this card.
- Card artwork generation — placeholder art is acceptable, consistent with every prior country-card spec.
- Re-balancing the cost, conditions, or mechanics of any other existing country card as a side effect of generalizing the Opinion-role resolution.
