# Spec: Declare War Card

## Feature Intent

As a player, I want to play a "Declare War" card naming one of the selected country's current rivals, so that I have a direct, player-facing way to turn an existing rivalry into an actual war instead of war only ever being reachable through the debug terminal.

## Acceptance Criteria

Legend: `Precondition => Action => Outcome`, grouped under a shared precondition where one applies to several rows.

- The selected country currently has no Rival relation with any other country.
  - The deck/draw system evaluates a free hand slot for this country => no "Declare War" instance is eligible to be drawn into the org's hand.
- The selected country currently has a Rival relation with another country (e.g. rival with Spain), and neither the ruler nor the military advisor of the selected (war-declaring) country currently holds 50 or higher opinion of the player's org.
  - The deck/draw system evaluates a free hand slot => no "Declare War" instance naming Spain is eligible to be drawn into hand.
  - Opinion later reaches 50 or higher for the ruler or the military advisor (or both) of the selected country => an instance naming Spain becomes eligible on the next free-slot draw, exactly like every other threshold-gated card — there is no "push the card into hand the instant the threshold is crossed" mechanic.
  - An instance naming Spain is already sitting in hand and that opinion later drops back below 50 for both roles => the instance is shown unplayable via the same conditions-gated check every other card already goes through; it stays in hand, it is not discarded.
- The selected country is rival with Spain, either the selected country's ruler or its military advisor holds 50+ opinion of the player's org, an instance naming Spain is in hand, and its 100-gold cost is affordable.
  - The card is shown as playable, labeled with the specific rival's name (following the same target-specific labeling style as "Stop Rivalry").
  - Its 100-gold cost is not affordable => the card is shown unplayable for the ordinary insufficient-funds reason, same as every other card.
- The selected country is rival with more than one country at once (e.g. Spain and Portugal simultaneously).
  - Hand/deck are evaluated => one independent instance exists per current Rival relation (one naming Spain, one naming Portugal); each instance's eligibility, drawing, and play are entirely independent of the other, mirroring how multiple "Stop Rivalry" instances already coexist.
- An instance naming Spain is sitting in hand, and before the player plays it the Rival(selected country, Spain) relation stops existing — cleared by another action, a debug command, or any other mechanic acting on that pair.
  - The player attempts to play that instance => the play is rejected/shown unplayable; it must not declare war on any other country and must not silently retarget itself to a different current rival.
- The player plays a "Declare War" instance naming Spain while the Rival(selected country, Spain) relation still holds, the opinion gate is met, the instance is playable, and its 100-gold cost is paid.
  - The play resolves => always succeeds, no roll of any kind; the card leaves the hand and a replacement is drawn into the vacated slot as usual, same as every other card.
  - Neither the selected country nor Spain was already at war with anyone => war is declared between the selected country and Spain, matching what the existing debug "declare war" command already does.
- The selected country is rival with Spain, the opinion gate is met, and either the selected country or Spain is already at war with a third country (its own or another rivalry).
  - The deck/draw system evaluates a free hand slot => no instance naming Spain is eligible to be drawn into hand.
  - An instance naming Spain is already sitting in hand => it is shown unplayable, for a distinct "already at war" reason (not the insufficient-opinion, insufficient-funds, or relation-no-longer-exists reasons).
  - The war(s) keeping either side occupied later end => the instance becomes playable/drawable again on the same gate re-check every other card already uses; no hand/deck change happens the instant the war ends.
- The player views the Action Log after playing "Declare War" and the war was actually declared.
  - An entry appears reporting that the selected country declared war on the rival it targeted.
- The player opens the country's Actions panel with this card, in either deck or hand state, at any time.
  - It never shows a cooldown label, and playing one instance never blocks another instance (naming a different rival, or a re-created instance for the same rival after a later re-declared rivalry) from being drawn or played — consistent with the project-wide removal of the cooldown mechanic.

## Tech Notes

- **Per-instance targeting reuses the existing "Stop Rivalry" plumbing exactly, rather than introducing a new component:**
  - `RelationCardTarget { string TargetCountryId; RelationKind Kind; }` (`src/Game.Components/RelationCardTarget.cs`) is reused unchanged — the same component `stop_rivalry` already carries, `Kind = RelationKind.Rival`.
  - `src/Game.Systems/RelationCardSyncSystem.cs` (`Update`) currently creates one `stop_rivalry` instance per rival relation via `EnsureCardInstance(world, orgId, countryId, otherCountryId, RelationKind.Rival, "stop_rivalry")` inside its `foreach (string otherCountryId in rivals)` loop. Add a second call in the same loop: `EnsureCardInstance(world, orgId, countryId, otherCountryId, RelationKind.Rival, "declare_war")`. This creates a second, independent card entity per rival relation (`GameAction{ActionId="declare_war"}` + `OrgContext` + `CountryContext` + `RelationCardTarget{TargetCountryId, Kind=Rival}`), never added directly to hand, following the exact "instance already exists → skip; never destroy" rule `EnsureCardInstance` already implements.
  - New static row in `Assets/Configs/action_config.json`, `actionId: "declare_war"`, `ownerType: "country"`, `targetRole: ""` (no single-role `OpinionModifierEffectParams`-style target — see the two-role opinion gate below), `deckCopies: 0` (all instances come from `RelationCardSyncSystem`, mirroring `stop_friendship`/`stop_rivalry`'s `deckCopies: 0` rows at lines 168/183 of that file), `cost: [{ "resourceId": "gold", "amount": 100.0 }]`, `effectIds: ["declare_war_effect"]`. `conditions` carries two checks: the existing `relationStillExists` gate (`{"type":"gte","members":[{"type":"relationStillExists"},{"type":"value","value":1}]}`, identical to `stop_rivalry`'s second condition) and a new gate described below.
- **New "ruler OR military advisor of the *war-declaring* country" opinion gate — genuinely new, no existing card gates on more than one character role (`ruler` and `military_advisor` instead of `diplomacy_advisor`):**
  - Every existing opinion-gated card (`make_friend`, `make_rival`, `stop_friendship`, `stop_rivalry`) resolves `ctx.Opinion` from `countryId`'s (the card's own `CountryContext.CountryId`) `diplomacy_advisor`. This card instead needs the max opinion held by that same country's `ruler` or `military_advisor` toward the player's org — same country as every other gate, different roles.
  - Add `TargetRulerOrMilitaryOpinion` (double) to `ExpressionContext` (`src/Game.Configs/ExpressionNode.cs`) and `case "targetRulerOrMilitaryOpinion": return ctx.TargetRulerOrMilitaryOpinion;` in `ExpressionNode.Evaluate`. `action_config.json`'s `declare_war` condition: `{"type":"gte","members":[{"type":"targetRulerOrMilitaryOpinion"},{"type":"value","value":50}]}`. (The expression type name retains the historical `target…` prefix from the initial draft; the value is computed from the declaring country's characters, not the rival's.)
  - This field must be computed **per entity** (only when that entity carries `RelationCardTarget`, matching `RelationStillExists`), at the same three call sites that field already touches:
    - `DrawCardSystem.DrawCountryCards` (`src/Game.Systems/DrawCardSystem.cs`, inside the per-entity loop at lines 107-125, alongside the existing `ctx.RelationStillExists = ...` assignment at line 117).
    - `ActionPlayability.Evaluate` (`src/Game.Systems/ActionPlayability.cs`, alongside its existing `relationStillExists` block at lines 24-28 — the method already takes `int entity` as a parameter from the prior "Stop Friendship/Stop Rivalry" work, so no signature change is needed here).
    - `VisualStateConverter.BuildEntry` (`src/Game.Main/VisualStateConverter.cs`, alongside its existing `relationStillExists`/`RelationCardTarget` block at lines 619-623).
  - Computation at each site (when `world.Has<RelationCardTarget>(entity)`): `var target = world.Get<RelationCardTarget>(entity); string rulerId = CharacterQuery.GetTargetCharacterByCountryAndRole(world, countryId, "ruler"); string milId = CharacterQuery.GetTargetCharacterByCountryAndRole(world, countryId, "military_advisor"); double rulerOpinion = string.IsNullOrEmpty(rulerId) ? 0.0 : ResourceQuery.GetValue(world, rulerId, $"opinion_{orgId}"); double milOpinion = string.IsNullOrEmpty(milId) ? 0.0 : ResourceQuery.GetValue(world, milId, $"opinion_{orgId}"); ctx.TargetRulerOrMilitaryOpinion = Math.Max(rulerOpinion, milOpinion);` — default `0.0` when the entity has no `RelationCardTarget` (unaffected for every other existing card, matching the `relationStillExists` default-1.0-when-absent / here default-0.0-when-absent convention: this field only ever gates `declare_war`, so an absent-component default of `0.0` is safe since no other card's `conditions` reference `targetRulerOrMilitaryOpinion`). Rival-country character opinion is intentionally ignored.
  - `CharacterQuery.GetTargetCharacterByCountryAndRole` (`src/Game.Systems/CharacterQuery.cs`) and `ResourceQuery.GetValue` are reused unchanged — both are plain, non-system query helpers already used by every existing opinion gate.
  - `VisualStateConverter.BuildEntry`'s existing unplayable-reason mapping (`src/Game.Main/VisualStateConverter.cs` lines ~636-645, matching on `fieldType`/`ContainsExpressionType`) needs a new branch: `"targetRulerOrMilitaryOpinion" => "insufficient_target_opinion"` (a new locale key `action.country.unplayable.insufficient_target_opinion`, alongside the existing `insufficient_opinion`/`no_suitable_target`/`relation_no_longer_exists` reasons), since this card's failed-opinion case is a distinct player-facing reason from the existing `"insufficient_opinion"` (which is specifically about the *own* country's diplomacy advisor).
- **New "neither side already at war" gate — confirmed with the owner: the card must go unplayable/undrawable instead of silently no-opping when `Wars.DeclareWar`'s own already-at-war guard would otherwise fire:**
  - Add `NeitherSideAtWar` (double) to `ExpressionContext` (`src/Game.Configs/ExpressionNode.cs`) and `case "neitherSideAtWar": return ctx.NeitherSideAtWar;` in `ExpressionNode.Evaluate`. `declare_war`'s `conditions` gains a third gate alongside `relationStillExists` and `targetRulerOrMilitaryOpinion`: `{"type":"gte","members":[{"type":"neitherSideAtWar"},{"type":"value","value":1}]}`.
  - Computed per entity at the same three call sites as `RelationStillExists`/`TargetRulerOrMilitaryOpinion` (`DrawCardSystem.DrawCountryCards`, `ActionPlayability.Evaluate`, `VisualStateConverter.BuildEntry`), default `1.0` when the entity has no `RelationCardTarget` (matching `relationStillExists`'s absent-component convention, since this field only ever gates `declare_war`). When `world.Has<RelationCardTarget>(entity)`: `var target = world.Get<RelationCardTarget>(entity); ctx.NeitherSideAtWar = (!Wars.IsInWar(world, countryId) && !Wars.IsInWar(world, target.TargetCountryId)) ? 1.0 : 0.0;` — `Wars.IsInWar` (`src/Game.Systems/Wars.cs`, already merged from the war-mechanics-core feature) is a plain static helper, reused unchanged the same way `Wars.DeclareWar` is reused below.
  - `VisualStateConverter.BuildEntry`'s unplayable-reason mapping gains `"neitherSideAtWar" => "already_at_war"` (new locale key `action.country.unplayable.already_at_war`), alongside the `insufficient_target_opinion` branch added above.
  - With this gate in place, `Wars.DeclareWar`'s own not-already-in-war guard (see the effect-resolution bullet below) is no longer reachable through ordinary play — it stays exactly as-is (untouched, per Out of Scope) as defense-in-depth against the same in-flight-tick race every conditions-gated card already tolerates (a hand entry evaluated one tick before its next gate re-check).
- **New effect: `DeclareWarEffectParams : ActionEffectDefinition`** (`src/Game.Configs/EffectConfig.cs`, no extra fields — the attacker/defender pair is already fully determined by the played entity's own `CountryContext`/`RelationCardTarget`, not by any static effect parameter), registered as `case "DeclareWar": item = obj.ToObject<DeclareWarEffectParams>(serializer)!; break;` in `ActionEffectDefinitionListConverter`'s switch (`src/Game.Configs/EffectConfig.cs`, alongside the existing six cases). One new `effect_config.json` entry, `declare_war_effect` (`effectType: "DeclareWar"`).
- **Play resolution — resolved inline in `CreateActionEffectSystem`, no marker component, no new system, no `GameLogic.cs` wiring, reusing the already-merged `Wars.DeclareWar` helper directly:**
  - New branch in `CreateActionEffectSystem.Update`'s `foreach (var effectId in def.EffectIds)` dispatch (`src/Game.Systems/CreateActionEffectSystem.cs`, alongside the existing `ClearCountryRelationEffectParams` branch at lines 106-109): `else if (effectDef is DeclareWarEffectParams && !string.IsNullOrEmpty(countryId) && world.Has<RelationCardTarget>(entity))` — reads `string targetCountryId = world.Get<RelationCardTarget>(entity).TargetCountryId;`, then calls `bool declared = Wars.DeclareWar(world, countryId, targetCountryId, currentTime);` (`src/Game.Systems/Wars.cs`, already merged from the war-mechanics-core feature — a plain static helper, not a "System", so calling it directly from inside `CreateActionEffectSystem`'s per-entity loop does not violate `.claude/rules/unity/ecs_patterns.md`'s no-system-to-system-calls rule, exactly as `EnemyControlDrainEffectParams`'s branch already calls the non-system `ControlQuery` helpers inline). `currentTime` is already a parameter of `CreateActionEffectSystem.Update`.

## Out of Scope

- Any UI for the player to manually pick which rival to declare war on, or to retarget an already-drawn instance — targeting is always automatic, one instance per current Rival relation, per the feature request.
- Retargeting a dead instance (whose named rivalry was cleared) to a different still-existing rival — a dead instance stays dead; a fresh instance for a re-formed rivalry with the same country reuses the same already-existing entity, exactly matching `stop_rivalry`'s reuse-on-reformation behavior.
- Any success/failure roll — always succeeds once played, per the confirmed requirements.
- Any cooldown or pacing/throttling mechanic for this card.
- Any change to `Wars.DeclareWar`/`Wars.IsInWar`/`Wars.StopWar` (`src/Game.Systems/Wars.cs`) themselves, or to `WarSystem`'s monthly progress decay — this card is purely a new caller of the existing, unmodified war-mechanics-core API.
- Any consequence of the war once declared beyond what `Wars.DeclareWar` already establishes (war progress, combat, peace resolution, AI reaction) — all out of scope for the underlying war-mechanics-core feature and untouched here.
- Re-balancing the cost, threshold, or mechanics of `make_friend`, `make_rival`, `stop_friendship`, `stop_rivalry`, `decrease_enemy_control`, `sphere_of_pressure`, the advisor cards, or `royal_audience`.
- Card artwork generation (placeholder art acceptable, consistent with every prior country-card spec).
- Opponent AI/bot strategy for choosing when to play this card or which rival to target — `Game.Bots/BotObservation.cs`'s existing `ActionPlayability.Evaluate` call site needs no signature change and no new bot heuristic is added; every instance is treated as interchangeable by bot decision-making, same as any other card today.
