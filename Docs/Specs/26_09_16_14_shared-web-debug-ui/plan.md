# Plan: Shared Web Debug UI

## Spec

Source: `Docs/Specs/26_09_16_14_shared-web-debug-ui/spec.md` (approved).

One finished Blazor WASM debug UI (`src/Game.WebClient/`, no v1/v2 split, no thin/fat publish) is the inspector for every host. Standalone WASM keeps screens A/B/D, settings, header/footer, and the in-game MENU overlay; its shared game view (C) adds freeze-tick and an ECS inspector beside the existing toolbar, actions log, and terminal. Unity Editor opens that same view in the **system browser** via `Application.OpenURL` (`DebugPanelDocument.OpenEcsViewer`) **without MENU**, landing on `?host=remote`; Unity WebGL keeps `btn-ecs-viewer` hidden. ConsoleRunner interactive prints `http://localhost:{port}?host=remote` and serves the same view (no menus); **Enter-to-step is replaced** by a ~30 Hz wall-clock loop; headless / `war-scenarios` / `war-idea` / `calibrate-end-game` are untouched. Play/Pause is `PauseCommand`/`UnpauseCommand`; freeze-tick is `PauseToken` — distinct controls. Inspector: enum-name dropdowns, domain-id dropdowns (config + live world), number inputs, omit large nested blobs, no EntityRef / `[EntityId]` work on `Game.Components`. Filters: existing +/- chips, entity-id substring, AND field filters (enum dropdown; number exact|min/max; string exact|contains|regex; invalid regex errors that row). Vanilla `index.html`/`app.js` is replaced. Duplicate HttpListener handlers collapse into one netstandard Newtonsoft handler with main-thread marshal, cheap `GET /hud` vs heavy `GET /snapshot`, `POST /command`, `GET /suggest`, and `GET|POST /pause` (freeze only). ID attributes move to `Game.Common` with new kinds; SuggestionEngine becomes netstandard so Unity/ConsoleRunner can run `/suggest`. One WASM `?host=remote` flag.

## Goal

Ship one Blazor debug surface reused in-process (standalone) and over HTTP (Unity Editor + ConsoleRunner interactive), with typed ECS snapshots, freeze-tick, and a unified netstandard viewer host — without moving game rules into Razor, without a second site, and without committing published `_framework/` binaries or placing them under `Assets/`.

## Approach

Per the spec's Tech Notes (referenced, not restated):

- **One WASM.** Keep `src/Game.WebClient/` (`net8.0`, `PublishTrimmed=false`). `.github/workflows/deploy-web-client.yml` stays. Remote hosts serve `dotnet publish` output from **`.tmp/web-debug-ui/`** (already gitignored via `.tmp/`; never commit `_framework/`). **Do not** copy into `Assets/StreamingAssets` (Blazor `.dll`s would hit PluginImporter; desktop player builds are out of scope).
- **Publish is part of plugin regen.** `scripts/unity/ensure_plugin_dlls.py` (and the matching `PluginDllRegenerator` watch/build path, which already shells the same Core DLL rebuild) also publishes Game.WebClient into `.tmp/web-debug-ui` when that tree is missing or older than `src/Game.WebClient/`. No separate User Step to remember a script.
- **IGameClient.** `InProcessGameClient` wraps `GameSession`; `RemoteGameClient` polls `GET /hud` (short) and `GET /snapshot` (long / on demand) and calls `/command`, `/suggest`, `/pause`, PATCH. `ShowPauseMenu` is true only in-process. Every remote URL includes `?host=remote` so menu routes are skipped. `Game.razor`'s `Logic == null => NavigateTo("/")` does **not** run when `HostMode.IsRemote`.
- **Shared Razor.** Extract toolbar, freeze-tick, keep `ActionsLog.razor` / `Terminal.razor`, add `EcsInspector.razor`. `Game.razor` composes those plus MENU when `ShowPauseMenu`. Inspector/filter chrome stays **English** (matches today's ECS viewer); standalone MENU/log/terminal keep existing locale keys — no new `en`/`ru` keys for freeze/filters.
- **Pause vs freeze.** Toolbar Play/Pause → `PauseCommand` / `UnpauseCommand`. Freeze → `PauseToken.IsPaused`. Host loops skip `BotSession`/`GameLogic.Update` while frozen; a `SimulationMarshal` (`ConcurrentQueue<Action>`) still drains so PATCH/`Push`/`Capture` run on the sim thread.
- **Attributes.** Move `ParamSuggestion.cs` to `src/Game.Common/`; add `ResourceId`/`CharacterId`/`WarId`/`BattleId`/`EffectId`/`TaskId`/`CollectorId`/`OwnerId`; add `OmitFromSnapshotAttribute`. Annotate existing `Game.Components` id fields. No analyzer; convention tests + docs/skill.
- **SuggestionEngine.** Move `src/Game.WebClient/Terminal/Suggestions/` into `src/Game.Commands.Text/Suggestions/` (already netstandard2.1 + Unity plugin). Replace `IGameConfigSource` with `ISuggestionSource` (config catalogs + live world) that `GameLogic` and tests can feed. Do **not** put SuggestionEngine in WebClient-only types.
- **Unified HTTP.** New plugin project `src/ECS.Viewer.Host/` (netstandard2.1, `OutputPath` `Assets/Plugins/Core/`, Newtonsoft with `ExcludeAssets` runtime like `Game.Configs.csproj`). `ViewerRequestHandler` owns path/method dispatch, MIME types, and JSON — **no** `HttpListener` in the plugin (WebGL still loads Host.dll). `ViewerServer` and `EcsViewerBridge` remain the `#if` / net8 listener wrappers. Serialization is **Newtonsoft**. API routes win over SPA fallback.
- **Layering.** `ECS.Viewer` stays ECS-only (`ECS.Core` only). Omit / domain-id / `OwnerTypeSibling` metadata is applied in `ECS.Viewer.Host` using `Game.Common` attributes (callback or wrapper around `Capture`).
- **Unity.** Edit `EcsViewerBridge` in place; **no new asmdef**. Add GUID refs on `GS.Unity.EcsViewer.asmdef` for `Game.Commands.Text` (`b8c3e0d194e91104a89a651356174bbd`) and `ECS.Viewer.Host.dll.meta` in the Host step (same pattern as existing `Game.Main` / `ECS.Viewer` GUIDs). WebGL stay: `#if UNITY_WEBGL && !UNITY_EDITOR` hides the button; listener compiled out of the bridge.
