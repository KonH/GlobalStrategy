# Spec: Decrease Enemy Control Card

## Feature Intent

As a player, I want to play a "Decrease Enemy Control" card on a selected country, so that I have a direct way to weaken whichever rival organization currently holds the most Control there while strengthening my own foothold in the same move, instead of Control only ever moving through passive income or cards that affect exclusively my own standing.

## Acceptance Criteria

Legend: `Precondition => Action => Outcome`, grouped under a shared precondition where one applies to several rows.

- The selected country currently has no organization other than the playing org holding any Control there.
  - The deck/draw system evaluates a free hand slot for this country => "Decrease Enemy Control" is not eligible to be drawn into the org's hand.
  - A copy is already sitting in hand from an earlier draw, and the condition later becomes false (the last other org's Control in this country drops to zero, e.g. cleared by another card or a debug command) => that copy is shown unplayable via the same conditions-gated check every other card already goes through; it stays in hand, it is never discarded or removed for this reason.
- At least one organization other than the playing org currently holds Control greater than zero in the selected country.
  - The deck/draw system evaluates a free hand slot => "Decrease Enemy Control" is eligible to be drawn like any other country card, subject to the normal per-slot draw fill — there is no "push into hand the instant the condition becomes true" mechanic; eligibility is only re-checked the next time a slot is actually being filled.
  - A copy is in hand and its 250-gold cost is affordable => the card is shown as playable.
  - A copy is in hand but its 250-gold cost is not affordable => the card is shown as unplayable for the ordinary insufficient-funds reason, same as every other card.
- The player plays "Decrease Enemy Control" while at least one other org holds Control in the selected country, and its 250-gold cost is paid.
  - Exactly one other organization currently qualifies => the play always succeeds, with no roll of any kind; that organization's Control in the country decreases by 20, clamped so it never goes negative (if it currently holds less than 20, it drops to exactly 0, not below); the playing org's own Control in the country increases by 10, subject to the same country-wide 100-point control-pool cap every other control-granting card already respects; the card leaves the hand and a replacement is drawn into the vacated slot as usual.
  - Two or more organizations qualify simultaneously (each holding Control greater than zero) => the play still only ever affects a single organization — the one with the currently highest Control total in that country (ties broken deterministically) — decreasing only that organization's Control by 20 (clamped as above); every other qualifying organization's Control is left untouched by that play.
- The player opens the selected country's Actions panel with this card in hand or in the deck pile, at any time.
  - The card never shows a cooldown label, and playing one copy never blocks another copy of the same card from being drawn or played — consistent with the project-wide removal of the cooldown mechanic.
- The player views the Action Log after playing "Decrease Enemy Control".
  - Two entries appear for that play: one reporting the targeted organization's Control decreasing by 20 (or by less, if it held less than 20) in that country, and one reporting the playing org's own Control increasing by 10 (or by less, if the shared pool had less than 10 points of room) in that country.

This reuses the existing "card sits in hand, shown unplayable, never removed" convention — no new UI mechanism is needed for the "becomes unplayable once the last qualifying org drops out" requirement.
  - New locale keys: `action.decrease_enemy_control.name` (placeholder, non-binding: "Undermine Influence"), `action.decrease_enemy_control.desc` — kept short and practical per `.claude/rules/unity/localization.md`'s rule for card descriptions, e.g. "Weaken a rival's control and strengthen your own."; `effect.decrease_enemy_control_drain.name`/`.desc` and `effect.decrease_enemy_control_gain.name`/`.desc` for the two new `effect_config.json` entries below. New `ActionVisualConfig` (`Assets/Scripts/Unity/Common/ActionVisualConfig.cs`, asset at `Assets/Configs/ActionVisualConfig.asset`) front-image entry keyed by `actionId: "decrease_enemy_control"` — placeholder art acceptable, art generation itself is out of scope (see below).

- **Architecture decision — no `RelationCardTarget`-equivalent component, no dynamic-instance sync system, this card sits in the "Make Friend/Make Rival" bucket, not the "Stop Friendship/Stop Rivalry" bucket:** `Docs/Specs/26_07_24_13_stop-friendship-rivalry-cards/spec.md` needed a per-instance `RelationCardTarget` component and a runtime `RelationCardSyncSystem` because each card copy had to stay bound to one specific, nameable relation pair for its whole lifetime (so it could be labeled "France is not a friend!" and re-check specifically whether *that* relation still holds). This feature's condition — "does any other org currently hold Control here" — is a single boolean shared identically by every copy of the card, exactly like `hasSuitableRelationTarget` (`Docs/Specs/26_07_24_10_country-relation-cards/spec.md`): the card never needs to name a specific enemy org while sitting in hand (nothing in the issue or in existing UI conventions requires that), so no per-instance identity, no new `[Savable]` component, and no entity-aware condition are needed. `ActionPlayability.Evaluate`'s existing `int entity` parameter (added for the Stop Friendship/Stop Rivalry work) needs no further change — this card's `Conditions` never read anything per-entity. The actual enemy org is instead resolved once, at effect-creation time, exactly like Make Friend/Make Rival resolve their candidate country at effect-creation time.

- **Target selection — the other org with the highest current Control, deterministic tie-break, grounded in an existing same-domain precedent (not the relation-cards' proximity/random precedent, which is a different domain):** `GameLogic.cs`'s private `GetOtherOrgsControlDescending` (lines 807-825, used by the debug `ForceControlInCountry`/`DebugForceCompletion` path) already ranks other orgs' Control totals in a country, descending, ties broken by `string.CompareOrdinal(OrgId)` ascending — the closest existing precedent, in the same `ControlEffect` domain this feature operates in. Decision: the play always targets the single other org with the highest current Control total in the selected country; ties broken the same way. New `ControlQuery.GetHighestControlOtherOrg(IReadOnlyWorld world, string orgId, string countryId)`: groups `ControlEffect.Value` by `OrgId` for `CountryId == countryId && OrgId != orgId`, returns the `OrgId` with the highest positive total, or `null` if none — same grouping shape as `GetOtherOrgsControlDescending`, but only the top entry is needed, not a full sorted list.

- **Play resolution — decrease by 20 (clamped) then increase by 10 (pool-capped), no roll, resolved inline in `CreateActionEffectSystem`, no new marker component or system, no `GameLogic.cs` wiring:**
  - New `EnemyControlDrainEffectParams : ActionEffectDefinition { public int Amount { get; set; } }` in `src/Game.Configs/EffectConfig.cs`, registered as `case "EnemyControlDrain": item = obj.ToObject<EnemyControlDrainEffectParams>(serializer)!; break;` in `ActionEffectDefinitionListConverter`'s switch (alongside the existing five cases). New `effect_config.json` entry `decrease_enemy_control_drain_effect` (`effectType: "EnemyControlDrain"`, `amount: 20`).
  - The self-increase half reuses the **existing, unmodified** `ControlChangeEffectParams`/`"ControlChange"` effect type — new `effect_config.json` entry `decrease_enemy_control_gain_effect` (`effectType: "ControlChange"`, `amount: 10`) needs no new C#; `CreateActionEffectSystem`'s existing branch (`src/Game.Systems/CreateActionEffectSystem.cs` lines 42-71) already does exactly "create a new `ControlEffect` for the playing org, capped by the shared 100-point pool" — unchanged.
  - New branch in `CreateActionEffectSystem.Update`'s `foreach (var effectId in def.EffectIds)` dispatch (alongside the existing `is ControlChangeEffectParams`/`is SetCountryRelationEffectParams`/`is ClearCountryRelationEffectParams` branches at lines 42/103/106): `else if (effectDef is EnemyControlDrainEffectParams drainParams && drainParams.Amount > 0 && !string.IsNullOrEmpty(countryId))` — resolves `ControlQuery.GetHighestControlOtherOrg(world, orgId, countryId)`; if non-null, reads the target's current total via this file's own existing private `GetOrgControlInCountry(world, targetOrgId, countryId)` helper (lines 128-139, reused as-is), computes `actualDrain = Math.Min(drainParams.Amount, targetControlBefore)`, calls the new mutating `ControlQuery.ReduceOrgControlInCountry(world, targetOrgId, countryId, actualDrain)`, and — when `actualDrain > 0` — emits a `ControlEffectApplied { OrgId = targetOrgId, CountryId = countryId, Delta = -actualDrain, Total = targetControlBefore - actualDrain }` Game Log event (see Game Log note below).
  - **No marker component, no new system, no `GameLogic.cs` orchestration change is needed.** Unlike `SetCountryRelationEffectParams`/`ClearCountryRelationEffectParams` (which defer to `SetCountryRelationSystem`/`ClearCountryRelationSystem` because they need `Random rng`/`ProximityMapData` not available inside `CreateActionEffectSystem`), resolving the highest-control other org and reducing its `ControlEffect` entities needs nothing beyond what `CreateActionEffectSystem` already scans (`ControlEffect` entities) and no randomness — so it applies synchronously inline, exactly like the existing `ControlChangeEffectParams`/`OpinionModifierEffectParams` branches.
  - **`effectIds` order is load-bearing:** `["decrease_enemy_control_drain_effect", "decrease_enemy_control_gain_effect"]` — the drain must run first so the reused `ControlChangeEffectParams` branch's existing `usedTotal < 100` pool-cap check sees the country's post-drain total, not the pre-drain one, guaranteeing the self-increase is never starved of pool room by its own card's drain.
  - New `ControlQuery.ReduceOrgControlInCountry(World world, string orgId, string countryId, int amount)`: collects every `ControlEffect` entity for `(orgId, countryId)`, sorts by `EffectId` (`string.CompareOrdinal`) for determinism, then reduces/destroys entries front-to-back until `amount` is consumed. **This is a near-identical reimplementation of `GameLogic.cs`'s private `ReduceOrgControlInCountry`** (lines 712-740, used by the debug `ForceControlInCountry` path, whose own comment already explains why a single-entity `ApplyChangeControl`-style update is wrong here: "an org's control in a country can span multiple `ControlEffect` entities ... this reduces across all of the org's effects"). `GameLogic`'s version is `private` and lives in `Game.Main`, unreachable from `Game.Systems`, so this feature adds its own copy rather than sharing it; consolidating the two into one implementation is a reasonable follow-up, not required for correctness here (see Out of Scope).
  - This is the first time `CreateActionEffectSystem`'s effect-dispatch pipeline destroys or shrinks a `ControlEffect` entity it did not itself just create in that same branch — every existing branch (`ControlChangeEffectParams`, `OpinionModifierEffectParams`, `DiscoverCountryEffectParams`) only ever adds new entities.

- **Cooldown-free (inherited, no new work):** no `cooldownDays`-equivalent field exists on `ActionDefinition` (`src/Game.Configs/ActionConfig.cs`) — already fully removed project-wide per `Docs/Specs/26_07_24_10_country-relation-cards/spec.md`'s Tech Notes. This card simply never carries any cooldown data, matching every other existing card.

- **Action Log — two entries per play, reusing the existing `ControlEffectApplied` component, fixing a real negative-`Delta` rendering gap:**
  - Both halves of this card's effect reuse the existing `ControlEffectApplied{OrgId,CountryId,Delta,Total}` component (`src/Game.Components/GameLogEffects.cs` lines 3-9) — no new Game Log component is needed. The self-increase half already emits one via the untouched `ControlChangeEffectParams` branch (lines 60-70 of `CreateActionEffectSystem.cs`); the new drain branch emits a second with a **negative** `Delta` — the first negative-`Delta` producer for this component; every existing producer only ever increases Control.
  - `GameLogLineFormatter.BuildControlLine` (`Assets/Scripts/Unity/UI/GameLogLineFormatter.cs` lines 16-22) currently hardcodes `"+" + FormatNumber(entry.Delta)` and always resolves `game_log.control_increased_format` — this would silently mis-render a negative `Delta` (e.g. "+-20"). Fix: branch on `entry.Delta >= 0`; the increase case keeps the exact current behavior and wording unchanged (`"+" + FormatNumber(delta)`, `game_log.control_increased_format`); the decrease case uses `"-" + FormatNumber(Math.Abs(entry.Delta))` and a new `game_log.control_decreased_format` locale key ("{0} decreased control in {1} by {2} ({3})"). `VisualStateConverter.UpdateGameLog` (`src/Game.Main/VisualStateConverter.cs` lines 798-811) and `CleanupEffectNotificationsSystem` need no change — both already forward/sweep `ControlEffectApplied` verbatim regardless of sign.

## Out of Scope

- Any success/failure roll for this card — it always succeeds once played, per the confirmed requirements.
- Any UI for the player to manually choose which enemy org gets targeted — target selection is always automatic (highest Control), per the feature request; no target-naming label is added to the card (see architecture decision above).
- Splitting the 20-point decrease across multiple qualifying enemy orgs — exactly one org is targeted per play, regardless of how many qualify.
- Any cooldown or new pacing/throttling mechanic for this card.
- Re-balancing the cost, amounts, or mechanics of any other existing country card (`sphere_of_pressure`, the advisor letters, `royal_audience`, `make_friend`/`make_rival`, `stop_friendship`/`stop_rivalry`) as a side effect of this feature.
- Card artwork generation — a new `ActionVisualConfig` entry is needed (see Tech Notes) but placeholder art is acceptable, consistent with every prior country-card spec.
- Consolidating the new `ControlQuery.ReduceOrgControlInCountry` with `GameLogic.cs`'s private, near-identical `ReduceOrgControlInCountry` — noted as a reasonable future cleanup, not required for this feature.
- Any change to the shared 100-point country control-pool cap mechanic itself, or to how `sphere_of_pressure`'s own pool-full unplayable reason works.
- Opponent AI/bot strategy for deciding when to play this card or how to weigh its target — `Game.Bots/BotObservation.cs`'s existing `ActionPlayability.Evaluate` call site needs no change (this feature doesn't alter that method's signature), and no new bot heuristic is added; every instance of this card is treated as interchangeable by bot decision-making, same as any other card today.
- Any gameplay consequence of a Control change beyond the Control data itself and its existing downstream consumers (monthly gold income via `ControlSystem.Update`, `org_score`/`country_score` collectors) — this feature only adds a new way to move `ControlEffect` values that already-existing systems already react to.
